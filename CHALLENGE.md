## Flaky Test Report

Our CI writes a JUnit XML file for every test run. Over time we end up with a directory full of
them, and somewhere in there is the information we actually care about: which tests cannot be
trusted.

Build a tool that reads a directory of these files and tells us what we need to know about test
reliability.

The `runs/` directory has nine files from recent CI runs to work against.

Use whatever language and libraries you like. Use whatever AI tooling you like, as long as you
understand what it produced.

### What we are looking for

Working software, and your judgment about what matters. There is more here than can be built in
90 minutes, so decide what is worth doing and tell us what you left out.

Send us a repo or a zip when the time is up.
